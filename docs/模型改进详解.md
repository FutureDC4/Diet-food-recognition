# 模型改进详解：CBAM + WIoU

> 状态：**代码已就位，暂不启用**。当前系统直接借用 DidntRead 的 `yolo11m.pt` 跑通全流程；
> 等中餐数据集（自建或开源，建议 ≥ 30 类 / ≥ 5000 张）准备好后，按本文档启用改进并训练。

---

## 1. 为什么改

当前流程的两个真实痛点：

| 痛点 | 现象 | 对应改进 |
|---|---|---|
| 背景干扰 | 盘边花纹、桌布、筷子、汤汁反光被误检 / 抢占注意力 | **CBAM**：通道+空间双注意力，压制背景、突出食物主体 |
| 小目标与重叠 | 一盘多菜时，小份菜（一勺麻婆豆腐）框不准，低质量样本梯度淹没有效梯度 | **WIoU**：动态非单调聚焦，自动降权离群样本 |

现行权重是 COCO-80（apple/banana/pizza…），类别形态差异大、背景单一，改进收益有限；
**中餐「多菜同盘 + 菜色相近 + 盘边干扰多」才是主要战场**，所以改进是为中餐数据集准备的。

## 2. CBAM 替代 C2PSA

### 2.1 位置

```
backbone:
  - [-1, 1, SPPF, [1024, 5]]         # 9
  - [-1, 1, CBAM, [512]]             # 10  ← 原为 [-1, 2, C2PSA, [1024]]
```

改的是 backbone 末端（SPPF 之后、送进 Neck 之前）的位置，**输入输出通道数一致，形状不变**，
因此 Neck 里 `[[-1, 10], 1, Concat, [1]]` 这种按层号索引的引用完全不用改。

> ⚠ 两个坑（实测 ultralytics 8.3.158）：
> 1. `parse_model` **不会**给自定义层自动补 `in_channels`，所以 CBAM 的通道必须写在 yaml 的 args 里；
> 2. 自定义层也不参与 width 缩放，而 SPPF 的输出会被缩放到 `min(1024, max_channels) × width`。
>    对 `yolo11m`（width=1.0, max_channels=512）就是 **512**，所以写 `[512]`。
>    换 n/s/l/x 缩放时要同步改这个数（n/s → 256，l → 512，x → 512）。
> 加载前必须注册模块：`import models`（`models/__init__.py` 会自动注册到 ultralytics）。

### 2.2 原因

- **C2PSA** 是 YOLO11 引入的位置-空间注意力，靠大卷积核做全局位置建模，参数量与显存占用都偏大，
  在「食物主体占据画面中心大块区域」的场景里属于过量建模。
- **CBAM** 更轻、更直接：
  - 通道注意力：`AvgPool + MaxPool → 共享 MLP(降维 reduction=16 → 升维) → Sigmoid`，
    自动学「哪些通道像食物」（颜色/纹理通道）。
  - 空间注意力：`通道维 mean + max → 7×7 Conv → Sigmoid`，自动学「画面哪一块是食物」。
- 参数量对比（以 1024 通道输入为例）：C2PSA 约 **2.6 M**，CBAM 约 **0.26 M**（降了约 90%），
  在同等检测精度下更省显存，也能开更大 batch。

### 2.3 为什么不用 SE / ECA

SE 只有通道维、ECA 只用 1D 卷积，都缺少空间维抑制；本场景「盘边 + 餐具」干扰主要在空间维，所以选 CBAM。

## 3. WIoU 替代 CIoU

### 3.1 位置

YOLO 的 `ultralytics/utils/loss.py` → `BBoxLoss.forward()`，默认 `self.iou_loss = CIoU`。
启用时把它换成 `WIoULoss(monotonous=False)`（v3 版本），输入仍然是 `(pred_boxes, gt_boxes)` 的 `xyxy` 张量。

推荐接入方式（不改 ultralytics 源码，训练脚本里猴子补丁）：

```python
from models.wiou import WIoULoss
from ultralytics.utils import loss as uloss

uloss.BboxLoss.__init__.__defaults__  # 仅示意，实际用下面的构造函数注入
# 训练脚本中：
model = YOLO("models/yolo11m-cbam.yaml").load("models/weights/yolo11m.pt")
# 在 trainer 初始化后替换：trainer.model.criterion[i].bbox_loss.iou_loss = WIoULoss(monotonous=False)
```

### 3.2 公式与三档版本

- `L_IoU = 1 - IoU`
- `R_WIoU = exp( ρ² / (W_g² + H_g²) )`：ρ² 为预测框与真值框中心距平方，`W_g/H_g` 为最小外接框宽高。
  该项**尺度不变**，且实现中做了 **梯度分离**（`detach`），不让距离项反过来产生「把框拉大」的捷径梯度。
- 动态聚焦权重 `r`：
  - v1（`monotonous=None`）：`r = 1`，即 `L = R_WIoU · L_IoU`
  - v2（`monotonous=True`）：`r = sqrt(β)`，单调聚焦
  - v3（`monotonous=False`，**本项目默认**）：`r = β / (δ·γ^(β-δ))`，β 超过 δ 后权重迅速下降，形成非单调聚焦
  - 其中 `β = L_IoU / mean(L_IoU)`，`mean` 用 7000 步 EMA 估计，`γ=1.9, δ=3.0`

### 3.3 为什么比 CIoU 好

CIoU 对每个框「等权」；一旦某批里混进标注粗糙/遮挡严重的离群框，它的巨大梯度会把整批训练带偏。
WIoU 把「离群程度」写进权重，相当于**自动做难例挖掘 + 噪声抑制**，在噪声标注数据集上尤其明显。

## 4. 启用清单（中餐数据集准备好后按顺序做）

1. 数据集：`data/chinese_food/data.yaml`，`names` 与 `data/food_reference.yaml`、`data/density_table.yaml` 的 key **完全一致**
2. 改 `models/yolo11m-cbam.yaml` 的 `nc` 为中餐类别数
3. `import models.cbam` 完成注册（`models/__init__.py` 已自动注册），确认 `YOLO('models/yolo11m-cbam.yaml')` 可加载
4. 迁移学习初始化：`YOLO('models/yolo11m-cbam.yaml').load('models/weights/yolo11m.pt')`（同名层权重自动继承）
5. 训练脚本里注入 `WIoULoss`（见 3.1）
6. 训练完成后把最好的 `.pt` 覆盖到 `models/weights/yolo11m.pt`，**代码零改动**即可推理

## 5. 消融实验计划

统一设置：同一数据集、`imgsz=640`、`epochs=100`、`batch=16`、`optimizer=SGD`、同一随机种子，只改模型/损失。

| 实验 | 结构 | BBox Loss | mAP50 | mAP50-95 | 参数量(M) | 单 epoch 耗时 | 备注 |
|---|---|---|---|---|---|---|---|
| A（基线） | yolo11m | CIoU | - | - | 20.1 | - | 对照 |
| B | yolo11m | **WIoU v3** | - | - | 20.1 | - | 只换损失 |
| C | yolo11m-**CBAM** | CIoU | - | - | ~17.7 | - | 只换注意力 |
| D（完整） | yolo11m-**CBAM** | **WIoU v3** | - | - | ~17.7 | - | 目标方案 |

判读标准：
- **B 相对 A** 提升 ≥ 1.0 mAP50-95 → 说明标注噪声/遮挡是主要瓶颈
- **C 相对 A** 提升 ≥ 0.5 且参数量下降 → 说明背景干扰是主要瓶颈，CBAM 性价比成立
- **D 相对 A** 提升 ≥ 1.5 → 论文/汇报可用的完整改进结论
- 若 D 低于 B 或 C，说明两者存在负交互（注意力把 WIoU 需要的梯度多样性压掉了），此时保留单项改进即可

## 6. 与当前系统的关系

当前 `src/detection/*` 一律走 `YOLO(models/weights/yolo11m.pt)` 的标准推理路径，
**不依赖也不加载** CBAM/WIoU。等到换成中餐模型（`weights/yolo11m.pt` 被替换）时：

- 若新模型是用 `yolo11m-cbam.yaml` 训练的，推理侧需先 `import models`（自动注册 CBAM）再加载，
  否则 ultralytics 解析自定义层会失败。`src/detection/*.py` 已在文件顶部做了 `import models  # noqa`，开箱可用。
- WIoU 只影响训练，推理完全无感。
